# 最终关修正与手机操作

最终关的对手改为两名困难电脑与一名中等电脑。判断权重没有再次重写：仍以补齐尚未收取的阵营为主要目标，普通模式及前十三关继续走各自原有策略。

## 一次只增加一个格子

棋盘最初有 16 个可用格。每次完整收取一个阵营，只沿外缘增加一个与旧棋盘正交连接的新格，因此格数依次为 16、17、18……64；共需要 48 次扩展才能达到完整的 8×8。同一阵营重复收取仍可扩展，获胜那次收取也会增加一格。只在弃牌堆攒齐阵营的判定继续保留，但不会凭空触发一次棋盘收取。

扩展先沿右侧增加，再补齐下侧，逐步形成下一个方形。比如第一个新格出现时，外接范围虽然是 5×5，但只有 17 格可用，剩下八格既不显示，也不能放牌、变成荒地或被 AI 当成位置。原有卡与荒地不移动。头像、抽牌区的推挤按照真实存在的格子计算，不会被尚未出现的区域推开。新增格播放短暂出现动画。

新版快照保存可用格数并检查空缺区域。旧版最终关快照保留原先已经存在的整块棋盘，导入后从下一次收取开始逐格增加，同时改用两困难、一中等的对手。

## 手机手牌与后台计算

- 在可滚动的手牌区直接滑动，会浏览手牌而不会立即拖起一张卡。滑动结束后的模拟点击会被拦截，避免误选释放位置上的牌。付款选牌时也可以滚动。
- 按住约 230 毫秒仍可抓起卡牌；在竖向手牌区向侧面拉出，也可以直接拖牌。新旧物理的运动方程都保留。
- 超过 30 张手牌时，手机只挂载当前窗口与缓冲行，滑动时补出后面的实体牌。横向手牌区同样处理。手牌模型、支付选择及卡牌编号不受影响；桌面仍显示完整手牌。
- 最终关的主行动推荐交给独立 Worker，主线程负责接收、验证合法性并执行。沿用同一评估函数，不修改卡牌价值。重试、退出或换局时终止 Worker 并取消待处理动作；不支持 Worker 或启动失败时回到原有分批计算路径。Worker 的结果不能越过已经结束的对局。
- 零代价的预览不再排序整副付款手牌。手机拖动影子保持轻量静态外观，真正创造牌在手机采用整个卡面的 CSS 色彩处理，避免大量 SVG 滤镜同时运行。

## 两种打印程度

最终关的 430 张普通副本使用轻微褪色和淡横纹，介于普通原牌与真正的创造牌之间；背景、立绘、阵营图标、收取方格与名字一起受影响。它们仍是普通卡，没有问号和额外代价。真正创造的卡保留更明显的缺墨效果、问号以及原有创造规则。其他模式的普通原牌保持原样。

## 收取后的环境

所有模式中完整收取阵营后切换背景环境。只维持最近一次的场景，博丽神社不触发切换。各场景共用两个过渡图层，手机至多四个粒子，桌面十二个；不创建逐粒子的 JavaScript 循环，不消耗对局随机数。减少动态效果时使用静态场景，重试或退出会清理背景。

## 验证范围

定向检查使用真实规则、渲染函数和手势处理器，覆盖 48 次逐格扩展、不可用格、旧快照迁移、140 张手牌末端访问、付款滚动、点击拦截、真实物理拖动入口、轻打印卡与创造选择、全部十种场景、取消清理，以及实际生成的 Worker 代码和主线程桥接。另运行受影响的历史回归与完整对局。

这些检查采用受控 DOM、几何和 Worker 通信，不能替代手机实机帧率与浏览器像素验收。

本次回归记录：16 套检查，855 项通过。两局最终关分别在 244、276 次主循环行动后结束，额外行动由实际控制器继续结算；每次主循环行动前后核对实体牌守恒。新增格边缘的一轮推牌另作实际支付和回牌堆结算检查。
